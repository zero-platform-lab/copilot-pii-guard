## 2. 目的と適用範囲

### 2.1 目的

伏せ字化がオンのとき、利用者が `@mask` へ依頼した文章、参照、会話履歴、ファイル内容、
ツールの結果から個人情報を取り除いたうえで、LLMに調査と編集を依頼できるようにする。元の値を
必要とする処理はローカルでだけ行い、LLMへ送り返さない。伏せ字化がオフのときは入力が生のまま
送られることを警告し、ファイルツールは停止する。

### 2.2 対象

- `@mask` との会話
- VS Codeが `@mask` へ渡した添付ファイル・選択範囲・文字列参照
- ワークスペース内のファイル一覧・検索・読取・書込
- ツール実行の承認、停止、失敗時の扱い
- 伏せ字の表示復元とファイル書込時の復元
- ファイルごとの伏せ字対応をセッション間で安全に保持するFile Vault
- エディタの右クリックによる検出確認

### 2.3 対象外

- 通常のCopilot Chatとコード補完への介入
- ターミナルコマンドの実行
- MCP、外部Web、外部サービスのツール
- サブエージェントとタスク委譲
- モデルが自ら権限設定を変更する機能

対象外の機能を追加する場合は、本書のツール一覧へ単純に足してはならない。機能ごとに送信経路、
副作用、承認、出力の伏せ字化を定めた別の脅威分析を先に作成する。

## 3. 前提と制約

### 3.1 VS Code APIの制約

- `@mask` が受け取れる履歴は、同じチャット参加者との履歴に限られる。通常のCopilotから
  途中で `@mask` へ切り替えた場合、それ以前の履歴は取得できない。
- `@mask` の参加者名や入力欄のラベルを、設定に応じて動的に変えることはできない。現在の
  モードは回答の先頭へ表示する。
- 利用できるモデルとツール呼び出しの能力は、VS CodeとGitHub Copilotが提供するモデルに
  依存する。
- 通常のCopilotが持つツール一式について、PII Guardは入出力の伏せ字化を保証できない。
  そのため一括して引き継がない。

### 3.2 安全側の既定

- 伏せ字化はオンを既定とする。
- 画面表示は元の値への復元を既定とする。
- ファイル書込は伏せ字のままを既定とする。
- ツール権限は、書込ごとに確認する `confirmEdit` を既定とする。
- ワークスペース情報へ触れる最初のファイル操作は、`@mask` の依頼ごとに利用者へ確認する。
- ファイルの書込は、利用者の確認を必須とする。
- ワークスペース外、未知のツール、シンボリックリンク経由のアクセスは拒否する。
- 伏せ字化がオフの場合は、すべてのファイルツールを無効にする。
- File Vaultは既定で無効とし、利用者がファイルごとに有効化する。
- File Vaultは最終利用から30日を既定の保持期間とし、0日は時間による期限なしを表す。
- 保持期間内でも、対象ファイルが存在しないことを確認した場合と利用者が消去した場合は削除する。

## 4. 用語とモード

### 4.1 3つの変換設定

次の設定は、データをどの形にするかを決める。ツールを実行してよいかどうかは決めない。

| 設定 | 対象 | オン | オフ |
| --- | --- | --- | --- |
| `piiGuard.enabled` | LLMへ送る入力とツール結果 | 伏せ字へ変換する | 生の値を送る |
| `piiGuard.restore` | LLMの回答を画面へ出す処理 | 元の値へ戻す | 伏せ字のまま表示する |
| `piiGuard.fileWrites.restore` | ツールがファイルへ書く処理 | 書込直前にローカルで戻す | 伏せ字のまま書く |

`Write Restore` は `piiGuard.fileWrites.restore` の表示名である。Write Restoreをオンにしても、
書込の承認を省略してはならない。モデルはこの設定を変更できない。

ファイル書込の実効動作は、2つの設定を組み合わせて決める。

| `piiGuard.enabled` | Write Restore | LLMへの送信 | ファイルツール | 書込内容 |
| --- | --- | --- | --- | --- |
| オン | 切 | 伏せる | 権限モードに従う | 伏せ字のまま |
| オン | 入 | 伏せる | 権限モードに従う | 書込直前だけ復元 |
| オフ | 切・入 | 生の値を警告付きで送る | 提示せず、呼ばれても拒否 | 書込不可 |

v0.2.5では、伏せ字化をオフにしてもファイルツールが残り、Write Restoreが切でも生の内容を
書き得る。次期版で上表へ統一するまで、伏せ字化をオフにした状態でファイルツールを使用しない。

### 4.2 ツール権限モード

変換設定と権限を混同しないため、次期版では別にツール権限モードを持つ。

| モード | 一覧・検索・読取 | 書込 | 位置付け |
| --- | --- | --- | --- |
| `off` | 提示せず、呼ばれても拒否 | 提示せず、呼ばれても拒否 | ツールを使わない |
| `readOnly` | 依頼ごとの初回に確認 | 提示せず、呼ばれても拒否 | 慎重な調査専用 |
| `confirmEdit` | 依頼ごとの初回に確認 | 毎回確認 | 既定・調査と編集 |

一覧にもファイル名が含まれるため、初回確認は一覧、検索、読取のいずれを最初に実行する場合にも
求める。承認はその `@mask` の依頼が終わるまでだけ有効とし、次の依頼へ引き継がない。

`readOnly` はファイルを変更しないが、伏せた内容をLLMへ送る。右クリックの「このファイルの
個人情報を確認する」はLLMへ何も送らず、ローカルで完結する別の操作である。

自動書込モードは本書の対象に含めない。権限モードを変更できるのは利用者だけとし、現在値を
回答の先頭と書込確認画面へ表示する。伏せ字化がオフの場合は、設定された権限モードにかかわらず
実効モードを `off` とする。

### 4.3 依頼、セッション、Session Vault、File Vault

- `依頼` は、利用者が1回 `@mask` へ送信してから、最終回答、停止または中断までの処理を指す。
- `セッション` は、VS Codeの拡張機能ホストでPII Guardが有効化されてから、再読み込みまたは
  終了されるまでを指す。
- `Session Vault` は、元の値と伏せ字の対応をプロセスのメモリ内だけに保持する対応表を指す。
- `File Vault` は、利用者が明示的に有効化したファイルについて、元の値と伏せ字の対応を
  暗号化して拡張機能専用領域へ保存する対応表を指す。

v0.2.5のLocal Vaultは、次期版でいうSession Vaultに相当する。セッション内で共通であり、
同時に開いた複数の `@mask` 会話から共有される。VS Codeの再読み込みまたは終了で失われる。

File Vaultはセッションをまたいで復元するための明示的なオプトイン機能とする。対象ファイル本体や
ワークスペース内へ対応表を埋め込まず、Git、Settings Sync、実行ログへ載せない。既定では
最終利用から30日保持し、設定値0は時間による期限なしとする。保持期間内でも、削除または
恒久的な消失を確認した場合は対応するFile Vaultを削除する。
VS Code外で行われた削除を扱うため、ワークスペース開始時とFile Vault利用前に存在を再確認する。

## 5. ユースケース

### UC-AGT-01 伏せて質問する（現行）

1. 利用者が `@mask` へ依頼する。
2. PII Guardが伏せ字化設定に従い、依頼、参照、同じ参加者の履歴を伏せる。
3. 伏せた会話だけをLLMへ送る。
4. LLMの最終回答を、表示設定に従って復元して表示する。

### UC-AGT-02 ワークスペースを調査する（次期）

1. LLMが一覧、検索または読取ツールを要求する。
2. PII Guardがツール名とパスを検査する。
3. その依頼で初めてワークスペース情報へ触れる場合は、対象と操作を利用者へ示して確認する。
4. 承認された場合だけローカルで実行する。
5. 結果とエラーを伏せてLLMへ返す。
6. LLMが調査を続けるか、最終回答を返す。

### UC-AGT-03 伏せ字のままファイルへ書く（次期）

1. LLMが書込内容を伏せ字を含む形で返す。
2. PII Guardが内容全体を再度伏せる。
3. 差分と `Write Restore: 切` を利用者へ示す。
4. 利用者が承認した場合だけ、伏せ字のまま保存する。
5. 完了結果を伏せてLLMへ返す。

### UC-AGT-04 元の値へ戻してファイルへ書く（次期）

1. 利用者が設定でWrite Restoreをオンにする。
2. PII Guardが書込内容を伏せた後、ローカルの対応表で書込直前だけ復元する。
3. 差分と `Write Restore: 入` の警告を利用者へ示す。
4. 利用者が承認した場合だけ、復元した内容を保存する。
5. 復元した本文はLLMへ返さない。

### UC-AGT-05 ファイルを変更せず確認する（現行）

1. 利用者がエディタの右クリックから「このファイルの個人情報を確認する」を選ぶ。
2. PII Guardが現在の検出設定で調べる。
3. 種類別の件数を表示する。
4. ファイルと伏せ字の対応表は変更しない。

### UC-AGT-06 中断または失敗から戻る（次期）

1. 利用者が処理を中断するか、モデルまたはツールが失敗する。
2. PII Guardが実行中のモデル要求とツール処理を中断し、新しい処理を開始しない。
3. 未承認の編集を破棄する。
4. 失敗理由を伏せて表示し、再実行できる状態へ戻る。

### UC-AGT-07 ファイルの対応表をセッション間で使う（次期）

1. 利用者が対象ファイルのFile Vaultを明示的に有効化する。
2. PII Guardがファイルに属する元の値と伏せ字の対応だけを、鍵と分離して暗号化保存する。
3. 次のセッションで同じファイルを扱うとき、File Vaultを復号し、今回のSession Vaultへ取り込む。
4. 複数ファイルの伏せ字が衝突する場合は、今回の依頼で一意な伏せ字へ再割当する。
5. 対象ファイルが存在しないことを確認した場合は、対応するFile Vaultを削除する。

### UC-AGT-08 保存した対応表を消去する（次期）

1. 利用者がSession Vault、現在のファイル、選択した複数ファイル、または全File Vaultを選ぶ。
2. PII Guardが消去対象のファイル数と対応数、消去後は既存の伏せ字を復元できないことを示す。
3. 利用者が確認した場合だけ対象を消去し、対象外のFile Vaultは変更しない。
4. 消去結果と、消去できなかった対象があればその理由を表示する。

| `FR-CTX-04` | 現行 | 読めない参照は送らず、利用者へ対象を知らせる |
| `FR-CTX-05` | 現行 | 伏せ字化がオンの場合、ツールの成功結果と失敗結果を同じ境界で伏せてからLLMへ返す |

| `FR-LOOP-12` | 次期 | 1つの依頼で実行するツール呼び出しを合計24件に制限する |
| `FR-LOOP-13` | 次期 | 1つの依頼で実行する書込ツールを合計8件に制限する |

| `FR-FILE-08` | 現行 | 一覧と検索では `.git` と `node_modules` を除外する |

| `FR-FILE-15` | 次期 | 検索対象ファイル数と返却結果数に別々の上限を設ける |
| `FR-FILE-16` | 次期 | NUL文字を含む入力パスを共通のアクセス判定で拒否する |

v0.2.5の検索は返却件数とは別に、候補の先頭200ファイルだけを走査し、この打切りを結果へ
表示しない。次期版では `FR-FILE-13` と `FR-FILE-15` に従って上限を分離し、打切りを明示する。

## 8. 機能設計

### 8.1 構成

| 構成要素 | 責務 |
| --- | --- |
| Chat Adapter | VS Codeの要求、履歴、参照、モデル、応答ストリームを受け渡す |
| Masking Boundary | LLMへ渡す文章をすべて伏せ、表示時だけ必要に応じて戻す |
| Agent Loop | モデル要求、ツール呼び出し、ツール結果、終了条件を管理する |
| Tool Policy | 提示するツールと、呼び出されたツールの実行可否を同じ規則で判定する |
| File Access Policy | ワークスペース、除外、パス、リンク、サイズを検査する |
| File Tools | 一覧、検索、読取、書込のローカル処理を行う |
| Edit Staging | 書込予定を保持し、差分、承認、競合検出、適用を管理する |
| Session Vault | 現在のセッションで使う元の値と伏せ字の対応をメモリ内に保持し、一意な割当、上限、同時更新、消去を管理する |
| File Vault Store | 明示的に有効化したファイルの対応表を暗号化保存し、鍵分離、保持期限、関連付け、存在確認、移動追従、消去を管理する |

### 8.2 送信とツール実行の流れ

伏せ字化がオンの場合の流れを示す。

```text
利用者の入力・参照・@mask履歴
              │
              ▼
       Masking Boundary
              │ 伏せた文章だけ
              ▼
             LLM
              │
       ┌──────┴──────┐
       │             │
   最終回答       ツール要求
       │             │
       │       Tool Policy
       │             │ 許可
       │      Read Approval
       │             │ 承認済み
       │       File Access Policy
       │             │
       │         File Tools
       │             │ 生のローカル結果
       │       Masking Boundary
       │             │ 伏せた結果だけ
       │             └──────► LLMへ再送
       ▼
表示設定に従って復元
       │
       ▼
     チャット
```

矢印はデータの移動方向を表す。Session VaultとFile Vaultは図中のMasking Boundaryと
書込直前の処理からだけ参照し、LLM側には置かない。File Vaultから読み込んだ対応は、
複数ファイル間で伏せ字が衝突しない形へ変換してからSession Vaultへ取り込む。

### 8.3 ツール契約

| ツール | 入力 | LLMへ返す結果 | 副作用 | 承認 |
| --- | --- | --- | --- | --- |
| `pii_guard_list_files` | glob、最大件数 | 伏せた相対パス | なし | 依頼ごとの初回 |
| `pii_guard_search_files` | 検索文字列、glob、最大件数 | 伏せたパス・行番号・該当行 | なし | 依頼ごとの初回 |
| `pii_guard_read_file` | 相対パス | 伏せた本文 | なし | 依頼ごとの初回 |
| `pii_guard_write_file` | 相対パス、全文 | 伏せた完了または失敗 | ファイル作成・置換 | 呼び出しごと |

パスと検索文字列に既存の伏せ字が含まれる場合は、ローカルでだけ復元して操作に使う。復元した
引数をLLMへ返さない。

### 8.4 ファイル内容と保存の意味

- 読取対象がVS Codeで開かれている場合は、未保存の編集を含むTextDocumentの内容を使う。
- 開かれていない場合はディスク上の内容を使う。
- 書込予定は現在のTextDocumentを基準に作り、承認画面を開く直前の文書版または内容ハッシュを
  保持する。
- 承認後に版またはハッシュが変わっていれば適用せず、差分を作り直す。
- VS Codeへ編集を適用した後、対象TextDocumentが未保存ならその状態を利用者へ知らせる。
- ディスクへの保存を実行する設計を採用する場合は、フォーマットや保存時処理で承認済みの差分が
  変わる可能性を扱い、実際の保存結果を確認する。

### 8.5 書込状態

| 状態 | 処理 | 次の状態 |
| --- | --- | --- |
| `received` | パス、権限、内容を検査する | `masked` または `rejected` |
| `masked` | 内容全体を伏せる | `restored` または `staged` |
| `restored` | Write Restoreがオンの場合だけ、ローカルで戻す | `staged` |
| `staged` | ディスクを変えず差分を作る | `awaitingApproval` |
| `awaitingApproval` | 利用者の判断を待つ | `applying` または `cancelled` |
| `applying` | 競合を再確認して変更を適用する | `completed` または `failed` |
| `completed` | 編集適用済みかディスク保存済みかを区別し、完了文を伏せてLLMへ返す | ループ継続 |
| `rejected` `cancelled` | ファイルを変えず理由を伏せて返す | ループ継続または停止 |
| `failed` | 失敗理由を伏せて返す | ループ継続または停止 |

現行版は `staged` の差分表示を持たず、確認後にVS CodeのWorkspaceEditを適用する。これは
TextDocumentへの編集適用であり、ディスクへの保存成功までは保証しない。次期版では承認前に
ディスクが変わらないことを保ったまま差分を表示し、適用後の保存状態を正確に通知する。

### 8.6 File Vaultの保存設計

- File Vaultの暗号文は、VS Codeが拡張機能へ提供するワークスペース固有の専用領域へ保存する。
- 暗号鍵は暗号文と分離し、VS CodeのSecretStorage相当へ保存する。
- ファイルの識別にはワークスペースと相対パスを使い、生の絶対パスを永続ログへ残さない。
- VS Codeが通知する名前変更と移動では関連付けを更新する。外部操作で通知を受け取れない場合に
  備え、ワークスペース開始時と利用前にファイルの存在を再確認する。
- 保持期限は最終利用からの日数で計算する。正常な読込または更新で最終利用日時を更新し、失敗した
  操作では更新しない。既定は30日、0日は時間による期限なしとする。
- 保持期間内または0日でも、対象ファイルが存在しなければ暗号文を削除する。存在確認に失敗した
  場合は存在しないと決めつけず、次回確認まで保持する。
- File VaultをSession Vaultへ取り込む際は、元の値が同じなら既存の伏せ字を再利用し、異なる
  元の値が同じ伏せ字を使っていれば、今回の依頼で一意な伏せ字へ再割当する。
- 復号できないFile Vaultは利用せず、利用者へ理由と個別消去操作を示す。自動で空のVaultへ
  置き換えない。
- 個別、複数選択、全体の消去を同じ削除境界へ通し、確認後に対象の暗号文、関連付け、有効状態を削除する。
  一括処理の一部が失敗した場合は、成功対象を元へ戻したように見せず、対象ごとの結果を表示する。

## 9. 脅威と対策

| 脅威 | 対策 |
| --- | --- |
| 入力欄や参照の生データが送られる | 送信関数を1か所に固定し、直前に会話全体を伏せる |
| ツールの読取結果から漏れる | 成功・失敗を問わずツール境界の外へ出る文字列を再度伏せる |
| ファイル名や例外文から漏れる | 本文と同じMasking Boundaryを通す |
| 検出漏れを含むファイル名や内容が意図せず送られる | ワークスペースへ触れる依頼ごとの初回に対象と送信リスクを示して承認を得る |
| 伏せ字化をオフにしたままファイルを読む | 実効権限を `off` にし、提示時と実行時の両方で拒否する |
| ファイル内の命令で権限を上げる | 権限は利用者設定だけで変更し、モデル用ツールを持たない |
| `..`、絶対パス、リンクで外部を読む | 共通のFile Access Policyで不正なパスとシンボリックリンクを拒否する |
| 提示していないツールを直接呼ぶ | 提示時と実行時の両方で同じTool Policyを適用する |
| 復元モードを承認不要と誤解する | 変換設定と権限を別軸にし、確認画面へ両方を表示する |
| 承認待ちにファイルが変わる | 版または内容のハッシュを再検査し、変化していれば中止する |
| モデルが同じ操作を繰り返す | 同一呼び出しと連続失敗を数え、上限で停止する |
| 1ラウンドで大量のツールを要求される | ラウンド単位、依頼単位、書込単位の件数上限を別々に適用する |
| Session VaultまたはFile Vaultが肥大化、衝突、同時更新で壊れる | 上限到達時に停止し、取込時の再割当と更新を直列化または原子的に行う |
| File Vaultから元の値が漏れる | 対応表を認証付き暗号で保存し、暗号鍵をSecretStorage相当へ分離する |
| File VaultがGitや同期へ混入する | ファイル横ではなくワークスペース固有の拡張機能専用領域へ保存する |
| 保持期限またはファイル削除後も対応表が残る | 開始時と利用前に期限と存在を確認し、期限切れまたは存在しないファイルのFile Vaultを削除する |
| 複数ファイルの同名伏せ字を誤復元する | File VaultからSession Vaultへ取り込む際、依頼内で一意な伏せ字へ再割当する |
| 鍵消失や暗号文破損で対応を失う | 復号失敗を表示し、既存暗号文を黙って初期化または上書きしない |
| 一括消去で意図しないFile Vaultまで失う | 対象範囲と件数を確認し、対象を固定してから削除し、対象ごとの結果を表示する |
| チェックポイントから個人情報が漏れる | 既定オフ、保存先分離、暗号化、鍵分離、保持と削除を実装前の必須条件にする |

## 10. 受入条件

| 対象 | 状態 | 最低限の試験 |
| --- | --- | --- |
| 送信境界 | 現行・次期 | 伏せ字化オンでは入力、参照、履歴、読取結果、検索結果、例外の各経路で生の値がモデルへ届かない |
| 伏せ字化オフ | 次期 | ファイルツールが提示されず、直接要求されても実行されない |
| 応答 | 現行 | 分割された伏せ字がストリーム境界をまたいでも正しく表示される |
| 読取承認 | 次期 | 各依頼の最初の一覧、検索または読取で確認し、拒否時はファイルへ触れず、次の依頼では再確認する |
| 権限 | 次期 | `readOnly` では書込ツールが提示されず、直接要求されても実行されない |
| パス | 現行 | 絶対パス、`..`、空要素、ドライブ名を拒否し、直接の読書きではシンボリックリンクを拒否する |
| パス共通化 | 次期 | NULを含む入力パスと全経路のシンボリックリンクを、共通のアクセス判定で拒否する |
| 除外 | 次期 | 一覧、検索、読取、書込のすべてで同じ除外パターンが効く |
| 検索上限 | 次期 | 検索対象数と返却件数を別々に制限し、打切り理由を返す |
| 書込取消 | 次期 | 拒否、中断、競合、差分生成失敗ではファイルが1バイトも変わらない |
| 保存状態 | 次期 | VS Code上への編集適用とディスク保存済みを区別し、未保存なら対象と必要な操作を通知する |
| 未保存文書 | 次期 | 読取と差分が未保存の編集を含み、承認待ちの変更を検出して上書きしない |
| Write Restore切 | 現行・次期 | 伏せ字化オンでは書込内容に伏せ字が残り、モデルへ生の値が返らない |
| Write Restore入 | 現行・次期 | 伏せ字化オンでは書込先だけが復元され、モデル、結果、ログには生の値が現れない |
| ループ上限 | 現行 | 12ラウンドで停止する |
| ループ停止条件 | 次期 | ツール件数、書込件数、同一呼び出し、連続失敗、空応答、タイムアウトで停止する |
| Session Vault | 次期 | 同時処理でも対応が壊れず、上限で停止し、明示的な消去後は既存の伏せ字を復元しない |
| File Vault保存 | 次期 | 既定では保存せず、有効化したファイルだけが暗号化され、平文、鍵、暗号文が同じ場所へ残らない |
| File Vault再利用 | 次期 | VS Code再起動後も対象ファイルの対応を利用でき、複数ファイルの伏せ字が衝突しても誤復元しない |
| File Vault保持 | 次期 | 最終利用から30日後に削除し、0日では時間削除せず、どちらも対象ファイルの消失確認後は削除する |
| File Vault移動 | 次期 | VS Codeによる名前変更と移動後も対応が追従し、旧関連付けを残さない |
| File Vault個別消去 | 次期 | 指定ファイルだけを消去し、他のFile VaultとSession Vaultを変更しない |
| File Vault一括消去 | 次期 | 選択した複数または全File Vaultの対象件数を確認し、部分失敗を対象ごとに表示する |
| File Vault障害 | 次期 | 鍵消失、暗号文破損、未知形式では利用を停止して理由を表示し、既存データを上書きしない |
| 状態表示 | 現行 | 伏せ字化とWrite Restoreの表示が実際の設定と一致する |
| 権限表示 | 次期 | 権限モードの表示が実際の設定と一致する |
| 右クリック確認 | 現行 | 種類別件数を表示し、文書とSession Vaultを変更せず、LLMへ送信しない |

新しい送信経路またはファイル経路を追加した場合は、既存の試験へ1件足すだけでは不十分である。
呼び出し箇所の一覧と件数を不変条件テストで更新し、すべての経路が共通境界を通ることを確かめる。

## 11. 段階的な実装

### 段階0: v0.2.5（現行）

- 4つのファイルツール
- ツール結果とエラーの再マスク
- 12ラウンドの上限
- 書込確認
- Write Restore
- 右クリックの検出確認
- 権限モードは未導入で、一覧・検索・読取に依頼単位の承認はない
- 書込はWorkspaceEditの適用までで、ディスクへの保存成功は保証しない
- 検索は候補の先頭200ファイルで打ち切り、その事実を表示しない
- Session Vault相当のLocal Vaultはセッション内の全会話で共有し、メモリ内だけに保持する

### 段階1: 権限とアクセス判定

- `off`、`readOnly`、`confirmEdit` の分離
- 伏せ字化オフ時のファイルツール停止
- 依頼ごとの最初のファイル操作に対する承認
- 提示時と実行時に共通のTool Policyを適用
- 全ファイル経路に共通のFile Access Policyを適用
- 利用者指定の除外パターン
- 検索対象数と返却件数の分離、および打切り表示
- ツール呼び出し数と書込回数の上限
- 同一呼び出し、連続失敗、空応答、待機時間による停止
- Session Vaultの上限、同時更新、表示、明示的な消去

### 段階2: File Vault

- ファイル単位の明示的な有効化と消去
- 対応表の認証付き暗号化とSecretStorage相当への鍵分離
- ワークスペース固有の拡張機能専用領域への保存
- File VaultからSession Vaultへ取り込む際の伏せ字衝突回避
- 最終利用から30日の保持、0日の期限なし設定
- VS Codeによる名前変更と移動への追従
- ワークスペース開始時と利用前の期限・存在確認、および期限切れ・対象消失後の削除
- Session Vault、個別File Vault、選択した複数、全File Vaultの消去
- 容量上限、破損時の安全な停止、消去の部分失敗表示

### 段階3: 安全な編集

- ディスクへ書く前の差分表示
- 承認待ちの競合検出
- 未保存のTextDocumentを含む読取と差分
- 編集適用後の保存状態の確認と表示
- 複数ファイルの一括承認と失敗時の整合性

### 段階4: 復元

- PII Guard専用のチェックポイント
- ファイルだけの復元
- 既定オフ、暗号化、鍵分離、保存場所、保持期間、削除の要件を満たした場合だけ実装

ターミナル、MCP、外部Web、サブタスクは段階4にも含めない。必要になった時点で別仕様を作る。

## 12. 未決事項

- タイムアウトと連続失敗回数の既定値
- 除外パターンをVS Code設定だけに置くか、ワークスペース内の専用ファイルも使うか
- 差分の承認をVS Codeの差分エディタで行うか、モーダル確認とチャット表示で行うか
- 複数ファイル変更をWorkspaceEditだけで扱うか、適用前の一時領域を持つか
- 編集適用後に利用者へ保存を任せるか、保存時処理の影響を扱って自動保存するか
- Session Vaultの登録数またはメモリ使用量の具体的な上限値
- File Vaultの1ファイル当たりの登録数、ファイル数、総容量の上限値
- File Vaultの認証付き暗号方式と鍵の世代管理
- VS Code外で行われたファイル移動を同一ファイルとして追跡するか、旧Vaultを削除して新規扱いにするか
- チェックポイントの暗号方式、保持期間、容量上限
- 大きな履歴を要約せず停止するか、伏せた履歴だけを別リクエストで要約するか

未決事項は、実装時の都合だけで決めない。個人情報が保存または送信される範囲、失敗時に
ファイルがどう残るか、利用者が画面から判断できるかを基準に決定する。
